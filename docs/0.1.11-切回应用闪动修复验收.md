# 0.1.11 切回应用后建议闪动修复

日期：2026-10-20。状态：源码候选检查通过，未安装；当前注册发行源仍为 0.1.9。此前用户已明确暂不安装，本次不变更这一选择。

## 问题与证据

用户截图显示：同一聊天已有两条建议，切换到其他应用再返回 Codex 后，短暂显示“等这轮回复结束”，约一秒后恢复。

在合成数据、冻结时钟的真实 Store 路径中，完成一轮生成后关闭租约、重新打开，再读取同一轮，旧实现返回 ready → waiting → ready，建议数量 1 → 0 → 1，没有新增模型调用。前端通过真实 Panel 和桥接测试替身重放此过程，“原有卡片不能消失”的断言先失败。

原因是新租约需要重新读取当前聊天，确认隐藏期间没有新一轮或配置变化；原实现将“尚未重新确认”与“当前一轮未结束”都称为 waiting。前端收到 waiting 后隐藏并删除卡片，之后恢复，产生闪动。另一个先失败的回归证明，同一聊天中带旧面板标识的较旧入口消息能绕过原来的状态版本保护。

## 修改

- 尚未重新确认的快照使用独立 syncing 状态，不再误称“等这轮回复结束”。后台继续隐藏未经确认的建议数据，过期保护不放开。
- 仅同一聊天、同一状态版本保留前端已经显示的卡片。同步期间显示短提示并禁用填入草稿；确认后恢复，同一份内容不重建 DOM，因此展开理由及滚动位置保留。
- 确认发现新一轮、配置变化、不同聊天、未绑定或读取错误时，不把旧预览当作可用结果。没有前端内存预览（首次打开或宿主重建页面）时显示“正在同步对话”。
- 拒绝较旧的同聊天入口消息，并撤销该旧面板租约，避免新状态被旧状态覆盖。
- 未改变服务层、模型生成适配器、推理参数、生成去重、手动刷新调度、密钥存储、API 地址或用户设置。草稿仍为 send:false，不自动发送。
- 包含之前 0.1.10 的目录修复，原独立 0.1.10 发行包继续保留。
