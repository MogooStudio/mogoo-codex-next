description: 打开 Codex 当前聊天右侧的下一步建议面板，配置该插件的独立模型，或诊断建议生成。用户要求使用或管理 Mogoo Codex Next 时使用；不接管原聊天任务，不在每轮回复后主动调用。
---

用户要打开面板时调用插件 MCP 的 `next_panel`，由宿主提供当前聊天标识。面板工具参数为空，不猜聊天 ID，不用最近活跃的其他聊天代替。右侧入口也可由用户直接打开。

建议由面板后台生成，不需要主 Agent 在每轮结束时调用插件。面板打开且自动生成开启时才允许模型请求；采纳只追加到输入框草稿，由用户发送。

模型由插件独立选择。官方模式复用 Codex CLI 登录；中转使用插件设置中的 Responses API 地址与直接填写的 API Key，不读取 Codex 本地中转配置。用户在面板中填写 Key，后台以 Windows 账户加密保存；公开设置只返回是否已配置。保存后留空保留旧 Key，填写新值替换；清除需点击 API Key 标题右侧的“清除”并保存，保存前可“取消清除”。更换地址需重新填写 Key。模型目录可读不等于可推理，成功推理才是调用证据。

CLI 入口位于本文件向上两级的 `scripts/run.py`，先解析实际安装位置。Windows 示例使用 `py -3`，macOS/Linux 使用可用的 Python 3：

- `python <入口> doctor`：检查资源和公开配置。
- `python <入口> doctor --probe-cli`：另检查只读 CLI 协议和模型目录，不推理。
- `python <入口> status`：读取插件配置与数据位置。
- `python <入口> configure --model <用户选择模型> --provider official`：保存用户明确要求的独立配置。

中转配置由用户在面板填写并保存。真实 Key 留在面板与后台，不索取到聊天、放入 CLI 参数或打印到诊断输出。旧版环境变量配置仅作兼容；面板填写新 Key 后替换。配置变更后核实实际加载版本，再验目录和推理。

安装与信任只能通过官方入口完成。不要修改 Hook 信任数据库、不要改 Codex 对话数据库或其他插件配置。Hook 为刷新优化；面板只读轮询是事件缺失时的兜底。

诊断时区分：静态资源就绪、MCP 协议就绪、真实面板聊天绑定、真实模型调用、真实草稿追加。这些证据不能互相代替。宿主缺少聊天标识或草稿扩展时明确说明：前者停止生成，后者提供复制，不退回自动发送。
